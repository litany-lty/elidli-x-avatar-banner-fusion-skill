# 背景与头像位置的几何规则

## 1. 为什么反复生成失败

页面布局中，横幅是裁切显示的**图层 A**，头像是 X 客户端叠加的**图层 B**，资料区域是不可编辑的**图层 C**。只修改 A；B 的圆心通常在 A 的底边之外。把 B 的完整圆圈复制画到 A 里，会造成两层圆心错位与黑框重复。

对 X 的适配是一种**遮挡关系与视觉延续关系**的设计，不是把两张图真正无缝拼为一张。

## 2. 坐标系与缩放

- 背景原图：`W × H`，坐标左上角 `(0,0)`，其中 `W/H=3`。
- 截图中的显示矩形：`(left,top,viewW,viewH)`。
- 截图头像圆心 `(screenCX, screenCY)`、外边框半径 `screenR`。
- 假设横幅采用 `object-fit: cover`、居中裁切：

```
scale = max(viewW/W, viewH/H)
scaledW = W * scale
scaledH = H * scale
cropX = (scaledW - viewW) / 2
cropY = (scaledH - viewH) / 2
imageCX = (screenCX - left + cropX) / scale
imageCY = (screenCY - top  + cropY) / scale
imageR  = screenR / scale
```

若 X 改为偏置裁切、不是 center、存在额外遮罩/缩放，需根据截图进一步修正；在没有截屏检验的情况下不要声称精确。

## 3. 可见相交弧

```
avatarTop = imageCY - imageR
visibleOverlapHeight = max(0, min(H, H - avatarTop))
```

如果 `avatarTop >= H`，说明头像没有压进横幅；如果 `imageCY <= H`，说明圆心已经在横幅内：两者都要重新核对截图与页面状态（也可能是不同客户端布局）。

在横幅底边 `y=H` 的两个交点（当 `abs(H-imageCY) < imageR`）为：

```
halfChord = sqrt(imageR² - (H-imageCY)²)
leftX = imageCX - halfChord
rightX = imageCX + halfChord
```

横幅**只能**画在 `y<=H` 区域。头像最靠上的位置 `(imageCX, imageCY-imageR)` 是浅弧的参照，横幅内可见弧随着 x 逐渐靠近底边。

## 4. 成功示例的经验性占位

以下仅用于**没有实测截图**时的首稿，不是全平台固定常数。成功素材分辨率 `1536×512`：

| 参数 | 参考值 | 作用 |
|---|---:|---|
| 头像圆心 x | 约 `210` | 横幅左侧约 `13.7%W` |
| 头像圆心 y | 约 `617` | 在横幅底边下约 `105 px` |
| 外边框半径 r | 约 `158` | 圆形直径约 `316 px` |
| 头像上沿 y | 约 `459` | 距底边约 `53 px` |
| 可设计弧顶 | 约 `420–470` | 接近头像顶部并留轻微外发光 |
| 弧线主要作用区 | x 约 `70–350`、y 约 `415–512` | **只作为初稿构图范围** |

这张示例成功依赖：顶部弧线**低**，其亮边可略高于头像实际顶部、连接流光**横向延伸**、底部岩层**薄**。不是在 x=200,y=300 画一个半径 160 的完整圆。

## 5. 适配不同设备

- X 的 iOS、Android、桌面网页、不同分辨率、缩放模式、页面折叠状态可能导致实际头像尺寸、位置或裁切变化。
- 如果上传后的横幅被垂直挪动或放大，无法用固定像素在所有设备同时“像素级完美”，只能选择一个主要展示端优先优化，再让其他端视觉上足够稳健。
- 首稿用经验性圆心，二稿用真实截图反推。每次不要扩大几何假设到“所有用户固定 10% 头像面积重叠”。
- 背景内可以略留多条过渡光丝，避免几像素偏差导致完全断线；但不要画不自然的第二个黑色头像边框。

## 6. 视觉检查

测算几何正确 ≠ 视觉一定融合。光效可能太亮、弧线太粗、头像本身与背景色差太大，或者被 UI 按钮遮挡。最终以真实 X 应用截图为准。
